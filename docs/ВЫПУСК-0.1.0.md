# Akhflow AI 0.1.0

Первый выпуск Akhflow AI объединяет трекер задач, веб-интерфейс и агента для работы с проектами. Агент обращается к локально настроенной языковой модели и выполняет доступные инструменты трекера от имени участника проекта. Запуск агента не предоставляет среду для выполнения кода или работы с репозиториями.

## Работа с задачами

В проекте можно вести задачи на доске и в списке, объединять их в эпики, задавать исполнителей, сроки и зависимости. Карточка задачи содержит критерии приёмки, комментарии, историю изменений и вложения. Критерии приёмки можно задать при создании задачи или изменить позже. Для повторяющихся задач предусмотрено создание следующих вхождений. Сводка показывает распределение задач по статусам, приоритетам и исполнителям.

Участники проекта работают с данными согласно своей роли. Роль viewer позволяет читать данные, editor позволяет также изменять их, а owner и admin могут управлять участниками. Веб-интерфейс получает уведомления об изменениях задач. При настроенной почте участник может включить уведомления об изменении статуса назначенных ему задач.

В выпуск входят импорт задач из Trello, Bitrix24 и сохранённого ответа Akhcheck, а также создание черновика ссылки на задачу для Telegram. Для импортов внешних сервисов нужны соответствующие настройки на сервере. Повторный импорт пропускает ранее загруженные записи и не перезаписывает локальные изменения.

## Агент

Агент доступен в чате проекта и из карточки задачи. Фоновый запуск продолжает работу после закрытия вкладки. В интерфейсе можно посмотреть состояние, шаги и итог запуска, а также запросить его остановку. Запуск из карточки сохраняет заголовок, описание и критерии приёмки задачи на момент отправки. Успешный запуск сам по себе не переводит задачу в другой статус.

Остановка не отменяет уже выполненные действия. Если результат начатого действия нельзя подтвердить, запуск получает состояние «прерван». После сбоя такой запуск не повторяется автоматически. Перед повторной отправкой запроса проверяем состояние задач и историю чата.

Владелец или администратор может задать инструкции агента для проекта. При создании фонового запуска сохраняются текст и версия инструкций. Позднейшие изменения не меняют контекст уже принятого запуска. При одновременном редактировании проверяется версия, чтобы не затереть сохранённый текст.

Агент использует инструменты трекера в пределах прав инициатора и проекта. Качество ответа и выбор действий зависят от настроенной модели. Синхронные запросы прежнего API продолжают работать отдельно от фоновых запусков.

## Установка и обновление

Приложение включает API, веб-интерфейс и PostgreSQL. Для фонового агента нужен доступ к настроенной модели через совместимый API. Подробности настройки и запуска приведены в документации проекта.

Миграции базы данных добавляют необходимые поля и таблицы. Перед ручным обновлением существующей установки сохраняем резервную копию базы и проверяем возможность восстановления. При запуске через Compose API применяет миграции при старте.

## Проверка перед публикацией

- Проверяем сборку Go, `go vet` и тесты на выбранном коммите.
- Собираем веб-интерфейс и запускаем проверки интерфейса для чата, фоновых запусков, карточки задачи и инструкций проекта.
- Проверяем миграции на изолированной базе и повторяем ключевые сценарии с несколькими участниками и ролями.
- Проверяем список инструментов MCP и выполняем сквозной запрос агенту в отдельном тестовом проекте с доступной моделью.
- Проверяем состав файлов и историю выбранного коммита перед созданием тега и публикацией.
