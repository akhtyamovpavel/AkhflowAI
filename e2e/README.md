# E2E-тестирование Akhflow (DSH-агент akhflow-e2e)

Агент `akhflow-e2e` — DSH-пресет для end-to-end проверки веб-приложения настоящим браузером
через **Playwright MCP** (headless Chrome). Он не читает код и не «верит» API: он открывает
UI, кликает, проверяет тексты и структуру, снимает скриншоты и отчитывается PASS/FAIL.

## Как запустить

1. Стек поднят: Postgres + API (:8080) + Vite (:5173). Проверка:
   `curl -s http://localhost:8080/api/health`, `curl -s -o /dev/null -w '%{http_code}' http://localhost:5173/`.
2. В DSH: новая сессия → пресет **Akhflow E2E** (`akhflow-e2e`) → промпт, например:
   - «Прогони e2e smoke по дефолтному сценарию.»
   - «Проверь, что история задачи #46 отображается в drawer и совпадает с audit_log.»
   - «Проверь создание задачи и перемещение todo → in_progress, потом удали тестовую задачу.»
   - «Найди регрессии после последних правок в drawer: скриншот каждого шага.»
3. Агент сам возьмёт токен из `.env` и подставит его в `localStorage("akhflow.token")`
   (в UI нет формы логина с известным паролем — вход по JWT).

## Скриншоты в выходах тулов

Ключевая особенность: `mcp__playwright__browser_take_screenshot` **без параметра `filename`**
возвращает изображение как image-контент результата — DSH показывает его прямо в диалоге.
Если передать `filename`, вернётся только ссылка на файл, а картинка — нет.

Файлы при этом автоматически складываются в `e2e/artifacts/` (в `.gitignore`):
скриншоты `page-<timestamp>.png`, ARIA-снапшоты `page-*.yml`, логи консоли `console-*.log`.
Каталог можно чистить: `rm -rf e2e/artifacts/*`.

## Дефолтный smoke-сценарий

| # | Шаг | Проверка |
|---|-----|----------|
| 1 | Канбан | проект **Akhflow**, 4 колонки Backlog/Todo/In Progress/Done, карточки, бейджи приоритетов |
| 2 | Drawer задачи | #46 (или #41): заголовок, статус/приоритет, «Зависит от»/«Блокирует», «Комментарии», «История (N)» — непустая |
| 3 | Эпик | фильтр «Все эпики» → «Импорт данных»: задачи #18–#20 |
| 4 | Список | переключение вида «Список»: строки, колонки, значения |
| 5 | Write-check | песочница `e2e-sandbox`: создать задачу `e2e-<timestamp>`, проверить на канбане, переместить todo → in_progress, скриншот, затем удалить через CLI |
| 6 | Сводка | ошибки консоли, упавшие запросы, сверка счётчиков с трекером через MCP |

Write-проверки выполняются **только** в проекте-песочнице `e2e-sandbox` (создаётся один раз
через «+ Проект»). В реальном проекте `akhflow` агент ничего не создаёт и не удаляет.

## Скриптовая проверка quick-add

Быстрый регресс-тест «задача из поля „Новая задача...“ попадает в Backlog» без GUI-сессии:

```bash
python3 e2e/verify_quick_add.py    # нужны API :8080, web :5173 и Chrome
# PASS → exit 0, скриншот e2e/artifacts/verify-quick-add.png
```

Скрипт берёт `@playwright/mcp` из npx-кэша (иначе `npx -y @playwright/mcp@0.0.83`),
подставляет JWT из `.env`, работает в песочнице `smoke-deps`, проверяет колонку Backlog в DOM
и `status=backlog` через REST, затем удаляет тестовую задачу. Временные кэши — в `.e2e-check/`
(gitignored).

## Требования к окружению

- Google Chrome в системе (`/usr/bin/google-chrome`) — Playwright MCP запускается с `--browser chrome`.
- Node.js 20+ (npx), сеть для первой загрузки `@playwright/mcp@0.0.83` (версия пиньится в пресете).
- DSH-профиль web с применённым фрагментом `scripts/dsh-akhflow-e2e.patch.yml`
  (в `~/.dsh/profiles/web/cordis.patch.yml`).
- Если Playwright-процесс не стартует, пресет помечается ошибкой (`failOnStartupError: true`) —
  смотрите диагностику в Settings → Agent presets.

## Известные особенности

- Токен в `.env` — JWT с истечением: при 401/экране «Войти» нужен свежий `AKHFLOW_TOKEN`.
- **Задача, созданная через поле «Новая задача...», попадает в колонку Backlog**: UI явно
  отправляет `status: "backlog"` (`web/src/App.tsx:687`). Серверный дефолт `todo` при пустом
  статусе (`internal/server/server.go:265`) остаётся для MCP/агента. Было исправлено в #732,
  в проверках ожидайте Backlog.
- `e2e-sandbox` и `*e2e-*` задачи после прогонов могут оставаться в трекере (удаление проекта
  через UI не предусмотрено); удаляйте задачи через `./bin/akhflow task delete <id>`.
- Скриншоты занимают контекст: 1 скриншот на значимый шаг, при длинных прогонах — compaction.
- Агент не чинит приложение и не коммитит: его отчёт — это баг-репорт, а не патч.
- Прогон можно выполнить без GUI через headless-DSH с той же композицией (persona + Playwright
  MCP + tracker MCP): временный `DSH_HOME` с профилем `headless`, re-enabled account credentials,
  задача подаётся на stdin. Скриншоты при этом всё равно падают в `e2e/artifacts/`.
