# Akhflow-AI

Akhflow-AI помогает вести задачи проекта и работать с ними через AI-агента. В приложении есть канбан, список задач, эпики, зависимости, повторяющиеся задачи, комментарии и вложения. Агент использует те же инструменты работы с трекером, которые доступны через MCP. Интерфейс приложения на русском языке.

Проект состоит из сервера на Go, веб-интерфейса на React и базы PostgreSQL. Для запросов агента нужен отдельный сервер модели с совместимым с OpenAI API методом `/v1/chat/completions` и поддержкой вызова инструментов.

## Быстрый запуск через Docker Compose

Понадобятся Docker, Docker Compose и доступный сервер модели. Из корня проекта:

```bash
cp .env.example .env
openssl rand -hex 32
```

Вставь сгенерированное значение в `JWT_SECRET` внутри `.env`. Для MCP через HTTP сгенерируй отдельное значение той же командой и запиши его в `MCP_API_KEY`. Храни `.env` локально и не добавляй его в Git.

Проверь `OLLAMA_HOST` и `AGENT_MODEL` в `.env`. Для модели на том же компьютере контейнеру нужен адрес хоста, например `http://host.docker.internal:11434`. Адрес `127.0.0.1` из контейнера указывает на сам контейнер. Если модель работает на другой машине, укажи доступный контейнеру адрес сервиса. В Compose настроен `host.docker.internal` через `host-gateway`.

```bash
make up
```

Открой `http://localhost:5173`, зарегистрируй пользователя и создай проект. API доступен на `http://localhost:8080`, проверка состояния: `http://localhost:8080/api/health`. При старте API применяет миграции. Для остановки контейнеров выполни `make down`; данные остаются в томе PostgreSQL.

Compose предназначен для локального запуска: пример содержит фиксированные учётные данные базы и открывает её порт. Перед размещением в сети настрой отдельные учётные данные, доступ к портам, TLS и резервное копирование. Образ приложения и пример Compose не выполняют такую настройку автоматически.

## Модель агента

`OLLAMA_HOST` задаёт базовый URL сервера модели без суффикса `/v1`. `AGENT_MODEL` задаёт имя загруженной модели. Сервер Akhflow отправляет запросы к `/v1/chat/completions` с описанием доступных инструментов. При использовании Ollama загрузи модель с поддержкой tool calling и убедись, что API доступен по выбранному адресу.

Клиент модели не добавляет API-ключ или другой заголовок авторизации. Для сервиса, который требует ключ, понадобится отдельно настроенный совместимый шлюз. Не открывай сервер модели без защиты в недоверенной сети. Настройки модели приложения не связаны с выбором уровней моделей для агентов разработки Codex.

## Локальная разработка

Для сборки нужны Go 1.26 и Node.js 22. Создай `.env` по примеру выше, задай `JWT_SECRET`, `DATABASE_URL`, `OLLAMA_HOST` и `AGENT_MODEL`. При локальном запуске API адрес PostgreSQL в `.env.example` подходит для базы из Compose, а адрес модели должен быть доступен непосредственно с компьютера.

```bash
make up-db
go build -o bin/akhflow ./cmd/akhflow
./bin/akhflow migrate
./bin/akhflow serve api
```

В другом терминале запусти интерфейс:

```bash
cd web
npm ci
npm run dev
```

Vite доступен на `http://localhost:5173` и передаёт запросы `/api` на локальный API с портом 8080. Запускай либо веб-контейнер Compose, либо Vite: по умолчанию они используют один порт.

## Агент и фоновые запуски

В чате проекта запрос создаёт фоновый запуск. Его состояние можно увидеть после перезагрузки страницы, а выполняющийся запуск можно попросить остановить. Повтор одного запроса с тем же `Idempotency-Key` возвращает исходный запуск. Если ответ на отправку потерян, интерфейс сохраняет ключ и предлагает проверить запуск перед осознанным повтором.

Запуск из карточки задачи сохраняет снимок её названия и описания и создаёт связанный чат. Повтор с тем же ключом возвращает исходный запуск, даже если задача изменилась. Удаление задачи удаляет связь с ней, но сохраняет чат и запуск. Успешный ответ агента сам по себе не переводит задачу в `done`.

Владелец или администратор может задать инструкции агента для проекта. Остальные участники могут их читать. Каждый новый фоновый запуск сохраняет снимок инструкций и их версии, поэтому изменение правил не меняет уже созданный запуск. При одновременном редактировании сервер отклоняет устаревшую версию, а интерфейс сохраняет черновик для сравнения. Инструкции не расширяют права пользователя или область доступа инструментов.

Доступные API фоновых запусков:

- `POST /api/chats/{id}/runs` создаёт запуск в чате; нужен заголовок `Idempotency-Key` с UUID и тело `{ "message": "..." }`.
- `GET /api/chats/{id}/runs` возвращает запуски чата, а `GET /api/runs/{id}` возвращает состояние и шаги запуска.
- `POST /api/runs/{id}/cancel` запрашивает остановку.
- `POST /api/tasks/{id}/runs` создаёт запуск для задачи с тем же форматом заголовка и тела; `GET /api/tasks/{id}/runs` возвращает её запуски.
- `GET /api/projects/{slug}/agent/instructions` возвращает инструкции и версию. `PUT` принимает `instructions` и ожидаемую `version`; устаревшая версия даёт ответ 409. Предел текста: 16 КиБ в UTF-8.

Остановка не отменяет уже выполненные действия инструментов. Если сервер потерял связь или завершился во время действия, результат может остаться неизвестным. Прерванные запуски не повторяются автоматически. Успешный результат, сохранённый до позднего запроса отмены, остаётся успешным. Проверяй состояние задачи и историю перед новым действием, если результат предыдущего не подтверждён.

Агент управляет трекером через доступные ему инструменты. Внешнего исполнителя кода, который клонирует репозиторий, меняет файлы и создаёт pull request по задаче, в приложении пока нет.

## Права и интерфейсы

Участник с ролью `viewer` читает данные проекта. `editor` может также изменять задачи и другие данные проекта. Существующая роль `member` сохраняет право записи. Управлять участниками и инструкциями агента могут `owner` и `admin`. Доступ проверяется сервером и общим реестром инструментов.

CLI использует `AKHFLOW_API` и `AKHFLOW_TOKEN` или флаги `--api` и `--token`:

```bash
./bin/akhflow task list -p <project-slug>
./bin/akhflow task get <task-id>
./bin/akhflow task move <task-id> --status done
./bin/akhflow agent "Покажи задачи проекта <project-slug>"
```

Для подключения MCP по stdio запусти `./bin/akhflow serve mcp`. Для HTTP используется `./bin/akhflow serve mcp --http :9090` и заданный `MCP_API_KEY`. `MCP_USER_ID` определяет пользователя, от имени которого работают инструменты MCP. Подробности команд доступны через `./bin/akhflow --help` и `--help` соответствующей подкоманды.

## Проверки

```bash
go build -o bin/akhflow ./cmd/akhflow
go vet ./...
go test ./...
cd web
npm ci
npm run build
```

Некоторые Go-тесты используют PostgreSQL и пропускаются без соответствующих переменных подключения. CI создаёт тестовую базу и задаёт переменные в [workflow](.github/workflows/ci.yml). Для браузерных сценариев нужен установленный Chrome и зависимости из `web`; примеры и дополнительные проверки находятся в [scripts](scripts/) и [e2e](e2e/README.md).

Дополнительные переменные для почты и импорта Trello или Bitrix24 перечислены в [.env.example](.env.example). Они необязательны для основного запуска. Учётные данные внешних сервисов задаются на сервере и не передаются через чат агента.
